home-lab

home-lab is a personal AI agent that runs on your own Mac, where risky actions wait for your signature and nothing leaves the machine by default.

Today it is for a technical person who wants to read the code and the evidence.

Read the status View the source

The approval rule

Every action the agent takes falls into one of four policy tiers. The tier decides whether the action waits for you.

  • Autonomous. Reading and listing run on their own.
  • Notify. Writing and fetching. These do not wait for a signature.
  • Approve. Deleting, shell commands, connector calls, skill scripts, MCP calls and copying a repository into a workspace. These wait for your signature.
  • Never. Refused. An approval does not apply. See the policy code.

An approve-tier action needs your Ed25519 signature over that exact action. Each approval covers one tool and its arguments. It works once and then expires.

The model only proposes. Rules and your signature decide.

Sources: CHANGELOG.md, SECURITY.md, COMPARISON.md.

Local by default

  • The model runs on your Mac. The model server listens on loopback only.
  • The agent runs as a separate lab account. That account is not an admin, cannot use sudo, and cannot read your approval key.
  • Skill scripts run in a disposable container with no network. This path is off unless you set it up.

Nothing leaves the machine by default. A web fetch goes through a default-deny egress gateway, and only a task that asks for one sends it. Three things send traffic out once you set them up: the heartbeat ping to an outside check, the alert to Telegram, and the paired Telegram chat.

Planned, not built: an opt-in hosted model, and an opt-in cloud runner, a second lab on a machine you rent, with your own key and the same signatures. Both are off by default.

Sources: README.md, SECURITY.md, CHANGELOG.md, FEATURE-PLAN.md.

Measured, not promised

Each claim was written down before the run that tests it. The results are as the documents state them.

  • M2, chat through the broker. 0 failures in 32 frozen cases. The model in the test was scripted to obey every injected directive. Source.
  • M5, untrusted code in a container. 0 failures in 30 frozen cases, run on the Mac on 2026-10-07. An outside observer could not see connections to public addresses, so those cases rest on the container having no network interface. Source.
  • M6, skill promotion. 0 failures in 36 frozen cases. No skill became active without a signed promotion. The rule that imported skill code runs only in the container is not tested yet. Source.
  • H4, isolation with the real model. 0 of 9 injection attacks succeeded. The model tried the injected action in 3 of the 8 scenarios where the handler ran, and the broker stopped all three. Registered on OSF. Source.
  • H1, local model routing. Not supported. On 30 labeled cases, accuracy was 0.10 against 0.83 for the fixed rubric, with five false promotions. This says that this model with this prompt fails. It does not say the model cannot do the task. Source.

No independent security review has been done. Do not connect real credentials.

Sources: PREREGISTRATION-SAFETY.md, PREREGISTRATION.md, CHANGELOG.md.

Build status

Running on the project's Mac mini

  • A task queue and supervisor. After a crash, tasks that are not safe to repeat wait for a person.
  • A local model on loopback: Qwen3-Coder-30B-A3B-Instruct, served by mlx-lm.
  • The lab as a non-admin lab account, since 2026-09-30.
  • Signed approvals. Approvals made without your key were refused in a test on 2026-10-06.
  • A paired Telegram chat. On 2026-10-07, /status and a plain message got the model's reply.
  • A watchdog that replaces a frozen supervisor. In two drills it took 96 and 97 seconds.
  • Backups. One was restore-checked by hand on 2026-10-07. The scheduled job has run once, by hand.

Built and tested on Linux, not yet run on the Mac

  • Three reviewed tools: workspace files, read-only git and web fetch with summary.
  • Repository copies, skill scripts and MCP calls, each as a reviewed handler.
  • Memory you can search, inspect, correct, revoke and delete.
  • Status and control commands, and a read-only status page on loopback.
  • Schedules you sign with your key. A due schedule adds a task to the queue. It never approves anything. Source.
  • A public injection suite of 27 cases you can rerun. Against a stub model that obeys every instruction it reads, 0 of 27 attacks succeeded. A run with the real model is next. Source.
  • A read-only check of the lab's own boundary: lab security-audit.

The lab has done no real work yet. Its queue is empty, and it holds no credentials.

Not yet proved on the Mac: the power-pull and interrupted-task drills, the network unplug test, and /stop from the chat.

Known gaps

These are not solved yet. The security gaps are listed in SECURITY.md.

  • One chat channel, Telegram.
  • No calendar or mail tools. There is no handler for either.
  • No voice, browser automation or companion apps.
  • No delegation tool and no session search.
  • No approval from your phone. Signing needs your key, which stays on the Mac.
  • One local model, and only the 32 GB memory tier has been measured. macOS on Apple silicon only.
  • No one-line installer yet. Updates are still run by hand: lab update --plan prints the steps for your install, and you run them.
  • No release has been tagged yet.
  • The local model did not route well on its own (H1).

Sources: COMPARISON.md, ROADMAP.md, README.md, CHANGELOG.md, FEATURE-PLAN.md.

Install

An install guide exists: INSTALL.md. It covers the requirements, a read-only prerequisite check, setup, the first run and uninstalling.

You need macOS 14 or later on Apple silicon, Git, the Xcode Command Line Tools, uv and an account that can use sudo during installation. Only the 32 GB memory tier has been measured.

git clone https://github.com/roshanaryal1/home-lab.git "$HOME/home-lab"
cd "$HOME/home-lab"
./scripts/check-prerequisites.sh

The fresh-account test on another Mac has not been run yet. Until it runs, the guide is not proved on a second Mac (issue 188).

Sources: INSTALL.md, README.md.

Not for

  • Anyone who wants to connect real accounts or credentials today. Use dummy data only. SECURITY.md lists the conditions before real credentials can be connected, and they are not all met.
  • Anyone who wants a hosted service. home-lab runs on your own Mac. A hosted model is planned, and it is off by default.
